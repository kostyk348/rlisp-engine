# Роадмап

Критерии этапов — дословно из роадмапа проекта (лендинг, `site/index.html`).
Статусы обновляются по мере реализации; «✅» — критерий проверен, «◐» —
реализовано с оговорками (оговорки перечислены честно), «○» — план.

## Этап 1 — wgpu за фасадом HAL, менеджер GPU-ресурсов, профилирование

**Критерий:** `--wgpu` · 100 reload без роста памяти
**Статус:** ◐ реализовано (этап 1 полностью; GPU-критерий — см. оговорку 1)

Что вошло (PR «Этап 1: wgpu за фасадом HAL»):

- Абстракция рендера за фасадом HAL: `enum Backend { Software, Wgpu }` +
  трейт `GpuBackend` (`clear / fill-rect / blit / blit-tex / tex_upload /
  tex_free / flush`). Lisp-нативы (`gpu-clear`, `gpu-fill-rect`, `gpu-blit`,
  `gpu-blit-tex`, `gpu-present`) и все скрипты не меняются — бэкенд
  выбирается на старте (`src/gpu.rs`, `src/hal.rs`);
- wgpu-бэкенд (опциональная фича `wgpu`, wgpu 0.20 / MSRV 1.75): headless —
  offscreen-таргет RGBA8 → WGSL-шейдер → copy-to-buffer → map-read →
  композит в `Hal::fb` по альфе-покрытию. PNG/ASCII/редактор/MCP работают
  без изменений. Дефолтная сборка — **ноль зависимостей** (проверяется в CI);
- `--wgpu`: без адаптера (CI/VM/headless) или без фичи — предупреждение и
  откат на программный растр, все скрипты продолжают работать;
- Менеджер GPU-ресурсов: книга хэндлов `GpuResources`
  (register/free/live/bytes/generation) + инвалидация при hot-reload
  (persistent-значения защищают свои текстуры). Подсчёт хэндлов покрывается
  тестами: стресс «100 create/reload циклов без роста памяти» — зелёный.
  Заодно устранена утечка v0.3 (~64 КБ/текстуру за reload);
- Профилирование: `--bench` замеряет синтетический 2D-кадр 320×240 на
  программном растре и (с `--wgpu`) на GPU: отдельно submit и readback,
  отдельно тот же кадр через интерпретатор (накладные расходы Lisp). Числа —
  в `docs/benchmark.md`, только из реальных запусков, с указанием окружения;
- CI (`.github/workflows/ci.yml`): fmt-check, clippy `-D warnings`,
  build+test с проверкой нуля зависимостей (`cargo tree`), wgpu-джоба
  (`cargo check/test --features wgpu`), smoke.sh. Триггеры: push в master и
  pull_request;
- Документация: `docs/architecture.md`, `docs/benchmark.md`, `CHANGELOG.md`,
  README (флаг `--wgpu`, раздел о бэкендах).

**Оговорки (честно):**

1. Критерий «`--wgpu` кратно быстрее» **требует GPU-железа**: все замеры
   этапа сделаны в headless-песочнице без адаптера, где wgpu-путь честно
   откатывается на программный растр. Класс ожидаемого эффекта записан в
   `docs/benchmark.md` как «ожидает проверки на железе» — числа не
   выдуманы;
2. wgpu закрывает **2D-растр** (clear / fill-rect / blit / blit-tex /
   present). 3D-конвейер (T&L, z-буфер, батчи) остаётся программным — это
   осознанная граница этапа 1; перед 3D-командой отложенный 2D-слой
   сбрасывается в fb, порядок художника совпадает с программным растром.
   Перенос 3D-батчей на GPU — тема этапа 5 (3D-игра на wgpu);
3. wgpu 0.20 выбран под rustc 1.83 (MSRV 1.75). Линейки wgpu 24.x/30.x
   требуют более свежий rustc — подъём версии будет отдельным изменением.

## Этап 2 — Полноценный Lisp: cons рядом с Vec, tracing-GC, потоки

**Критерий:** `(cons 1 2)` · 1000 циклов замыканий · MCP не крашит игру
**Статус:** ✅ реализовано (этап 2; оговорки — ниже)

Что вошло (PR «Этап 2: полноценный Lisp»):

- **cons-пары рядом с Vec**: `Value::Cons` — cons-ячейка в GC-куче; Vec-списки
  (`Value::List`) сосуществуют. `cons` строит пару — `(cons 1 2)` → `(1 . 2)`;
  `car`/`cdr`/`set-car!`/`set-cdr!`/`cons?`/`pair?`/`list?`/`length`/`append`/
  `reverse`/`nth`/`apply`/`list->vector`/`f32-from-list` работают с обоими
  представлениями, `equal?` сравнивает цепочки структурно (и с Vec-списками).
  Печать стандартная: `(a b c)` и `(a . b)`, циклы не зависают (`…`). Reader
  читает точечные пары и сигнатуры `(lambda (a . rest) …)`, quasiquote ходит
  по парам;
- **tracing-GC (mark-sweep), ноль зависимостей** (`src/gc.rs`): арена объектов
  Pair / Lambda / Env с хендлами (индекс+поколение) в `Value`. Маркировка от
  корней (глобальное окружение, RAII pin-наборы, очередь ввода), обход
  прозрачен для Rc-контейнеров, sweep освобождает непомеченное. Примитивы
  `(gc)` и `(gc-stats)`, авто-сборка по порогу аллокаций. Критерий проверен
  тестом и smoke-строкой: 1000 циклов «замыкание ↔ окружение → снял корень →
  собрал» — живых объектов в куче ровно базовая линия на каждом круге;
- **потоки**: MCP-сервер переведён на фоновые потоки (reader разбирает stdio
  в mpsc-канал → игровая нить применяет запросы между кадрами → ответы через
  канал writer'у stdout). Интерпретатор — однопоточный владелец Lisp-
  состояния, Values/Hal не покидают игровую нить, гонок по построению.
  Критерий «MCP не крашит игру»: тест на 120 инструментов поверх живой игры
  3D (все отвечены, ноль паник) + smoke-молотилка на 102 запроса;

**Оговорки (честно):**

1. **Сборка — только на границах форм** (когда стек вычислителя пуст):
   значения в локальных переменных рекурсивного `eval` недоступны обходу
   корней. `(gc)` и авто-порог честно откладываются до границы; `collect()`
   во время eval — паника-детектор. Для игрового цикла (кадр = несколько
   форм) это означает паузы ≤1 мс на кучах в сотни тысяч объектов
   (замер — `docs/benchmark.md`);
2. **В куче — пары, замыкания, окружения**; Rc-контейнеры (`Vector`,
   `F32Vec`, `Table`, строки) остаются на Rc и для маркировки прозрачны
   (содержимое защищается, пока контейнер жив). Но Rc-циклы *через сами
   контейнеры* (таблица, ссылающаяся на себя) по-прежнему не собираются —
   это осознанная граница этапа;
3. **Цена интерпретации**: микробенчмарк чистого TCO-цикла замедлился ~1.5×
   (1.24 → 1.83 с на 10⁶ итераций, та же песочница — замер в
   `docs/benchmark.md`); накладные расходы Lisp в кадре с нативами не
   изменились (0.26 мс/кадр). Возврат скорости — тема этапа 3 (JIT);
4. Из «потоков» этапа сделан MCP-канал (критерий этапа). Фоновые задачи
   общего вида (аудио, ресурсы) — этап 4 роадмапа.

## Этап 3 — JIT (copy-and-patch, Cranelift), SIMD в токенизаторе и GC, деоптимизация

**Критерий:** eval ≥5× · парсер ≥3× · property-тесты ловят JIT-баги
**Статус:** ◐ реализовано (PR «Этап 3: SIMD-токенизатор + zero-dep JIT», #7;
числа — `docs/benchmark.md`)

Что вошло:

- **JIT числовых ядер** (copy-and-patch, ноль зависимостей — без Cranelift:
  собственный IR + x86-64 эмиссия): IR-компилятор горячих числовых лямбд
  (арифметика, сравнения, if/and/or, let), const-pool, гард арности/типов,
  нативный вызов; runtime-деоптимизация при непредвиденных формах (например
  деление на 0) — возврат в интерпретатор без потери состояния. Критерий
  **eval ≥5× — выполнен**: вызов числовой лямбды 2296.5 нс (interp) →
  46.8 нс (JIT) = **49.07×** (200k вызовов, песочница);
- **SIMD-токенизатор** (byte-class скан SSE2/AVX2) + property-тесты interp vs
  JIT (3000 выражений, seeded xorshift) и взаимная сверка AST scalar-vs-simd
  на реальных исходах. Критерий **парсер ≥3× — НЕ выполнен** (1.07×,
  числа в benchmark.md, разбор причин там же) — читатель честно помечен;
- кэш скомпилированных лямбд (индекс+поколение GC), `--features jit`,
  дефолтная сборка — ноль зависимостей.

Оговорки: JIT — только числовые лямбды (остальной код — интерпретатор);
SIMD-скан на лексемах Lisp длиной 3–8 байт выигрыша не дал (осознанно,
см. benchmark.md); Cranelift за фичей не подключался — zero-dep правило
репозитория победило.

**Критерий:** посторонний играет 5 минут без падений
**Статус:** ◐ реализовано с оговоркой (см. ниже)

Что вошло (в этапе 6, ветка stage6/editor-demo):

## Этап 6 — Редактор: gizmo-манипуляторы, drag-n-drop префабов, сохранение сцены в Lisp

**Критерий:** сцену можно собрать мышкой и сохранить в .lisp
**Статус:** ◐ реализовано с оговорками (ветка stage6/editor-demo)

Что вошло:

- **гизмо-манипуляторы**: X/Y/Z-стрелки над выбранной сущностью в видовой
  порт (та же проекция, что в `render3d.lisp`: камера приходит из хука
  `(editor-camera)` через `/api/state`); тяга оси мышью → дельта в мировых
  единицах (от экранного якоря старта тяги) → `(table-set! …)` через
  `/api/eval` — сущности двигаются в живой игре (проверено: drag по X
  x 6.0→12.42 при неизменном z); клик по виду выбирает ближайшую сущность;
- **drag-n-drop префабов**: панель ПРЕФАБЫ из хука `(prefab-list)`
  (grunt/brute/pylon), перетаскивание на вид → обратная развёртка пикселя в
  луч → пересечение с плоскостью мира → `(mcp-spawn-at 'kind x z)`;
- **сохранение сцены**: кнопка «Сохранить сцену» → `POST /api/save-scene` →
  игровая нить вызывает `(editor-save-scene "scene_saved.lisp")`
  (editor.lisp) → формы восстановления через натив `file-write`:
  враги/пилоны → `(mcp-spawn-at 'kind x z)`, игрок → `(table-set! *player*
  'x …)`; пули/взрывы (переходящие) пропускаются. Возврат в игру —
  `(load "scene_saved.lisp")` через REPL. Round-trip покрыт unit-тестом
  (3 сущности → файл → reader → load → те же позиции);
- пилоны стали полноценными сущностями игры (spawn/remove, отдельный батч в
  отрисовке, persistent);
- полировка: сетка-привязка 0.5, хоткеи (G — гизмо, Del — удалить),
  тосты, fps в паузе не врёт, страница редактора пересобрана (на master
  она была битой с первого коммита — рендерился пустой лист);
- скрины живого редактора: `demo/editor-*.png` (реальные скриншоты
  headless-браузера поверх `--serve`).

**Оговорки (честно):**

1. гизмо — 2D-оверлей над PNG-стримом кадра (~4 Гц): камера игры непрерывно
   движется, между опросами состояния оверлей чуть отстаёт от кадра; тяга
   компенсирует это якорем старта, но пиксель-точность Full-редактора
   (Unity-like) не достигнута;
2. drag-n-drop и клик-выбор работают в браузере (HTML5 drag events);
   скриншоты сняты headless-браузером;
3. ось Y гизмо двигает свойство `y`, только если оно есть у сущности
   (у врагов/пилона игры его нет — стрелка рисуется, но честно подсказывает);
4. сохранение сцены фиксирует позиции в момент нажатия: враги в живой игре
   продолжают двигаться, «восстановление» возвращает их в сохранённые точки;
   загрузка файла — ручная через REPL (кнопки «Загрузить сцену» нет).

## Этап 7 — Графика v2: материалы (alpha-test, Blinn-Phong, тайлинг, туман)

**Критерий:** материалы в 3D-конвейере: alpha-test · блик · тайлинг · туман
**Статус:** ◐ реализовано с оговорками (ветка stage7/materials)

Что вошло (PR «Этап 7: материалы»):

- **Alpha-test (cutout)** в текстурных 3D-гранях: `(gpu3d-alpha-test
  threshold)` — тексель с alpha < порога отбрасывается до записи в
  z-буфер (семантика GPU-`discard`); за дыркой билборда/забора видна сцена.
  Это фундамент растительности будущей демо-сцены;
- **Блик Blinn-Phong**: `(gpu3d-light dx dy dz ambient [diffuse [spec
  [shininess]]])` — опциональные аргументы, per-pixel half-vector на
  перспективно-корректной мировой позиции (новый атрибут вершины «мир/w»),
  камера — `(gpu3d-view x y z)`; spec 0 = старый Lambert байт-в-байт;
- **Тайлинг UV** `(gpu3d-mat-tiling u v)` (repeat через fract, (1,1) —
  прежний clamp) и **экспоненциальный туман** `(gpu3d-fog r g b density)`
  по истинной глубине 1/w, смешение после шейдинга;
- **Lisp-слой материалов** `assets/lisp/materials.lisp`:
  `(defmaterial …)` / `(use-material! …)` / `(material-reset!)`; draw-хелперы
  принимают опциональное имя материала, все прежние вызовы работают;
- **инспекция** `(gpu3d-state)` — таблица состояния конвейера;
- **бенчмарк 3D-шейдинга** в `--bench` (одна сцена, 5 конфигураций): база
  Lambert 6.85 мс/кадр; дельты реальных прогонов — alpha-test +3.9%,
  блик +46.4%, туман +14.6%, весь материал +59.3% (docs/benchmark.md);
- **визуальное доказательство**: `scripts/materials_proof.sh` — 4 варианта
  одной сцены, PIL-сверка пикселей, коллаж `demo/stage7-materials.png`;
- 9 новых юнит-тестов + 5 smoke-проверок; fmt/clippy чисто, дефолтная
  сборка — ноль зависимостей.

**Оговорки (честно):**

1. alpha-blending в 3D нет — только alpha-test (z-буфер без сортировки
   прозрачности); туман применяется к непрозрачным поверхностям; каркас
   (`gpu3d-wire`) не освещается и не затуманивается;
2. нормали граней flat — блика на сглаженных нормалях нет (Gouraud не
   заявлялся);
3. новые фичи — только в программном 3D-пути; wgpu-бэкенд (этап 1)
   не затронут, паритет с GPU задокументирован как ожидание этапа 8+;
4. по пути найден и исправлен баг мастер-ветки: перепутанная связка
   `f32::sin_cos` (возвращает (sin, cos)) ломала матрицу любого
   батч-инстанса — см. LIMITATIONS.md.

## Этап 8 — wasm-таргет, мобильный таргет, fallback SIMD

**Критерий:** одна .lisp-сцена работает на десктопе и в браузере
**Статус:** ○ план

План: wasm-сборка ядра (интерпретатор переносим, HAL уже за фасадом —
wgpu-native → webgpu), мобильный таргет, скалярный fallback SIMD как
эталон эквивалентности.
